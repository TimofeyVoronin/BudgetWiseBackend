# ADR 0005: Offline-first доменные области

## Статус

Принято.

## Контекст

Приложение должно поддерживать работу без сети для основных финансовых сценариев. Пользователь должен иметь возможность открыть приложение, просмотреть сохранённые данные, создать или изменить ключевые записи, а после восстановления сети отправить изменения на сервер через API синхронизации.

В рамках текущего этапа не включаются отчёты и финансовые цели. Эти области не входят в MVP offline-first, чтобы не усложнять синхронизацию и не смешивать основные пользовательские действия с вычисляемой аналитикой.

## Решение

Offline-first scope фиксируется в коде через реестр доменных областей `apps.finance.sync.domains` и отдаётся frontend через API:

```text
GET /api/v1/finance/sync/domains/
```

Также краткая информация о доменных областях включена в:

```text
GET /api/v1/finance/sync/meta/
```

## Доменные области

### Базовые финансовые данные

Ресурсы:

```text
accounts
categories
transactions
tags
```

Назначение: основная работа пользователя с финансами без сети. Позиции операции `line_items` синхронизируются внутри ресурса `transactions`.

### Планирование

Ресурсы:

```text
budgets
transactionTemplates
recurringTransactions
plannedTransactions
```

Назначение: работа с бюджетами, шаблонами, регулярными и плановыми операциями. Эти данные используются для будущих списаний, прогноза и финансового календаря.

### Справочники финансовых форм

Ресурсы:

```text
currencies
```

Назначение: сохранённые валюты пользователя, основная валюта, видимость валют и пользовательские валюты. Обновление внешних курсов валют не является offline-first действием, потому что требует сети.

### Фискальные чеки

Ресурсы:

```text
receipts
```

Назначение: просмотр уже сохранённых чеков и их позиций. Получение данных от внешнего провайдера чеков требует сети. Созданные из чеков финансовые операции синхронизируются через ресурс `transactions`.

### In-app уведомления

Ресурсы:

```text
notifications
```

Назначение: просмотр серверного состояния уведомлений. Email и push-уведомления не входят в текущий scope.

### Вычисляемые снимки интерфейса

Snapshots:

```text
dashboard
financialCalendar
```

Назначение: отображение последнего серверного снимка для главной страницы и финансового календаря. Эти области не отправляются в `push`, потому что являются вычисляемыми на основе счетов, операций, плановых и регулярных операций.

## Исключённые области

В текущий offline-first scope не входят:

```text
goals
reports
receiptProvider
currencyRates
email
pushNotifications
```

Причины:

- `goals` исключены из текущего согласованного scope;
- `reports` являются вычисляемой аналитикой;
- `receiptProvider` и `currencyRates` требуют сети;
- email и push будут подключаться позже.

## Последствия

Frontend может использовать `sync/domains/` как единый источник правды для структуры IndexedDB, кэша и UI-состояний синхронизации. Backend сохраняет список поддерживаемых ресурсов централизованно и не размазывает правила offline-first по отдельным view.
