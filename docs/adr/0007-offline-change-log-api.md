# 0007. API журнала оффлайн-изменений

## Статус

Принято.

## Контекст

Приложение поддерживает offline-first сценарий: пользователь может создавать и изменять финансовые данные без сети, а затем отправлять изменения на сервер пачкой. Для устойчивой синхронизации серверу нужен журнал обработанных операций, чтобы повторный запрос не создавал дубли, а фронт мог показать состояние синхронизации и историю попыток.

## Решение

Для журнала оффлайн-операций используется модель `OfflineSyncOperation`. Каждая операция определяется комбинацией пользователя, `clientId`, `deviceId` и `clientMutationId`. Эта комбинация уникальна и обеспечивает идемпотентность.

Для чтения состояния синхронизации добавлены endpoint-ы:

- `GET /api/v1/finance/sync/status/` - краткая сводка состояния синхронизации;
- `GET /api/v1/finance/sync/operations/` - постраничный журнал обработанных sync-операций.

`sync/status/` возвращает счётчики операций по статусам, число конфликтов и последние операции. `sync/operations/` поддерживает фильтры по статусу, ресурсу, действию, клиенту, устройству и `clientMutationId`.

## Ограничения

Endpoint-ы возвращают только операции текущего пользователя. Журнал не заменяет основной `pull/push` механизм, а используется как вспомогательный API для отладки, UI-состояния синхронизации и проверки идемпотентности.

## Последствия

Фронт может показывать пользователю состояние синхронизации и историю обработанных изменений. Повторная отправка уже применённой операции с тем же `clientMutationId` не создаёт дубль, а возвращает сохранённый результат.
