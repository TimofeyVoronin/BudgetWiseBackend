# ADR-0002: Подход к хранению static и media файлов

## Статус

Принято

## Контекст

Backend-проект может использовать два типа файлов:

- `static` - статические файлы приложения и Django admin;
- `media` - пользовательские загружаемые файлы.

На текущем этапе проект ориентирован на REST API для финансового приложения. Основная бизнес-логика связана с пользователями, счетами, категориями, операциями, бюджетами и отчетами.

Пользовательские media-файлы пока не являются ключевой частью MVP. Возможные будущие сценарии:

- загрузка аватара пользователя;
- загрузка изображения чека;
- хранение файлов экспорта отчетов;
- временное хранение сформированных PDF или XLSX-файлов.

## Решение

На текущем этапе используется базовый локальный подход:

```python
STATIC_URL = "static/"
STATIC_ROOT = BASE_DIR / "staticfiles"

MEDIA_URL = "media/"
MEDIA_ROOT = BASE_DIR / "media"
```

Локальные директории `staticfiles/` и `media/` не должны попадать в Git.

Для production-среды допускается дальнейшее развитие подхода:

- отдача static-файлов через reverse proxy, например Nginx;
- хранение media-файлов во внешнем объектном хранилище;
- подключение специализированного storage backend, если появится такая необходимость.

## Последствия

Преимущества решения:

- простая настройка на этапе разработки;
- не требуется подключение внешнего файлового хранилища на раннем этапе;
- подход совместим с Django и может быть расширен позже;
- решение не усложняет MVP лишней инфраструктурой.

Ограничения решения:

- локальное хранение media-файлов не подходит для масштабируемого production;
- при запуске нескольких экземпляров backend-сервиса потребуется внешнее хранилище;
- для production нужно отдельно настроить отдачу static и media файлов.

## Альтернативы

Рассматривались следующие альтернативы:

1. **S3-совместимое объектное хранилище**

   Такой подход хорошо подходит для production, особенно при горизонтальном масштабировании. На текущем этапе он избыточен, так как требует дополнительных настроек, ключей доступа и отдельной инфраструктуры.

2. **Хранение файлов в базе данных**

   Этот вариант упрощает резервное копирование, но плохо подходит для больших файлов и усложняет отдачу файлов клиенту.

3. **Полный отказ от media-файлов**

   Такой вариант возможен на самом раннем этапе, но он ограничивает будущие функции, например загрузку чеков, аватаров или файлов отчетов.

## Итог

На этапе MVP используется локальная схема хранения static и media файлов. Она проста для разработки и не мешает будущему переходу на production-подход с reverse proxy или объектным хранилищем.
