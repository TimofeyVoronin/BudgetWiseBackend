# ADR 0012: Celery и Redis для фоновых задач

## Статус

Принято.

## Контекст

В серверной части есть операции, которые не должны зависеть от ручного запуска команд и HTTP-запросов:

- конвертация планируемых операций в фактические операции;
- выполнение регулярных операций;
- обновление курсов валют пользователей.

Ранее эти сценарии можно было запускать через management-команды. Для локальной разработки и дальнейшего production-развёртывания нужен единый механизм фоновой очереди и расписания.

## Решение

Для фоновых задач используется Celery, брокером и backend для результатов выступает Redis.

В проект добавлены:

- `config/celery.py` с Django-интеграцией Celery;
- `apps/finance/tasks.py` с задачами финансового модуля;
- сервисы `redis`, `celery_worker`, `celery_beat` в `docker-compose.yml`;
- настройки `CELERY_*` и `REDIS_*` в `config/settings/base.py`;
- health-check Redis и Celery в `/health/`;
- Prometheus-метрики для Redis и Celery.

Celery Beat запускает задачи по расписанию:

- `apps.finance.convert_due_planned_transactions` каждый день в 00:05;
- `apps.finance.run_due_recurring_transactions` каждый день в 00:10;
- `apps.finance.refresh_currency_rates` каждый час.

Текущие management-команды остаются в проекте. Они полезны для ручной проверки, локальной отладки и аварийного запуска.

## Последствия

Плюсы:

- фоновые операции отделены от HTTP-запросов;
- появляется единая очередь для тяжёлых задач;
- регулярные и планируемые операции можно выполнять автоматически;
- обновление курсов валют можно запускать по расписанию;
- Redis и Celery видны в health-check и метриках.

Ограничения:

- локальный запуск теперь поднимает дополнительный Redis-контейнер;
- для production потребуется отдельный worker-процесс и Redis/Key Value сервис;
- email и push-уведомления пока не включаются, они будут подключаться отдельной задачей.
